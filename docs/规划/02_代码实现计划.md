## 第一部分 · 各域实现计划

### 后端实现架构师

**实现策略**：【策略】后端按「统一地基 + 三域出口」重构，以 P0 为主、P1 全纳入（时间充足）。核心决策：

1. **技能注册表（P-1）是唯一 LLM 底座**：把 `backend/app/services/llm_service.py` 的 9 个硬编码方法重构为 `SkillRegistry.run(task, payload)` 统一入口，技能集中到 `services/skills/`（每个技能 = Skill 元数据 + pydantic 输出 schema + 版本化 prompt 文件在 `services/prompts/<skill>/<version>/`）+ `llm_client.py`（指数退避重试 + 超时 + 可注入缓存/脱敏钩子）。旧 6 路由迁移到 `run()` 且**行为不变**（MockLLM 回归集 ≥15 条锁定，S0 先迁 classify/extract_todos/extract_exams/summary/consult 打样）。`llm_service.py` 保留旧方法名作兼容垫片（转发到 run），避免一次性重写 6 路由导致的回归。
2. **数据模型 P-2：严格"只建新表不 ALTER 老表"**（规避无 Alembic 启动即崩，已在 main 裁决核实）。原始材料层复用 documents/chunks，新增 `document_tags` 做检索池隔离；档案层新增 `archive_records`（evidence 为显式列：evidence_document_id/chunk_id/page/confidence + sensitivity + record_status）；生成物层新增 `artifacts`（版本链 parent_artifact_id + source_ids JSON + export_path）；支撑表 todo_links/task_progress/papers_meta/signups/signup_entries/ledger_entries/audit_logs(P1)。`database.init_db()` 幂等 create_all 仅新增 import，老表不动。
3. **证据链契约统一**：`Evidence{source_document_id, chunk_id, page, confidence}` 冻结进 ADR，AI 回答/简历行/综述段都带 evidence，无来源标【待补充】，前端 CitationChip 统一消费。
4. **安全 P-4 挂 run() 前置钩子**：main.py 绑定 127.0.0.1（已默认）、CORS 收为 loopback 白名单（dev 用 `localhost/127.0.0.1` 任意端口正则，规避 Flutter web 随机端口）、X-Local-Token 校验、写接口限流；redaction/consent/demo 三钩子经 skill_registry 的 pre_run 统一注入，演示模式默认豁免。
5. **长任务 P-9**：`task_service.py` 提供同步阻塞 + map-reduce 分段（单篇 <4000 字符）+ task_progress 分步更新，前端轮询。
6. **统一导出 P-3**：`export_service.py` 用 python-docx/openpyxl 生成 WPS 兼容 docx/xlsx，经 `/api/files/{path}` 提供下载 URL；App 运行时导出由后端自身生成（独立于离线 /docx /xlsx skill 场景）。
7. **意图路由 P-1**：`orchestrate` 技能 + `POST /api/ai/orchestrate`，6 条演示指令全路由到正确 domain，不明时返回澄清引导而非硬路由/报错。
8. **演示模式 P-5**：`demo_mode.py` + `routers/admin.py`(seed/clear/demo-status) + `seed_data/seed_demo.py`（林小夏三合一档案）。
9. **前端契约影响**（归前端架构师执行，本稿冻结 API 字段）：api_config.dart 需新增 X-Local-Token 头注入与 /api/career、/api/papers、/api/affairs、/api/tasks、/api/admin、/api/ai/orchestrate、/api/files、/api/export 端点；AppScaffold 由 6Tab 改 5Tab IndexedStack 属前端域。

【里程碑对应】S0：模型+幂等建表+注册表打样+安全三件套+导出骨架+seed/clear+回归集；S1：career 路由与技能；S2：papers；S3：affairs；S4：跨模块打通（inbox→archive、signup→todo、papers→knowledge）。功能冻结 9/14。

**风险**：
  - 无 Alembic 迁移：任何对老表 ALTER 都会启动即崩（已核实）。硬约束=只建新表、只改路由逻辑，新需求字段一律进新表（如 todo_links 承担 todos 来源角标，archive_records 独立成表）。
  - 重构 llm_service 触发既有 6 路由回归：用 MockLLM 回归集 ≥15 条锁定行为 + 旧方法名兼容垫片，S0 先迁 2-3 个高复用技能打样，迁移一批回归一批。
  - X-Local-Token / CORS 收紧会瞬时打断前端联调：ENABLE_TOKEN 默认 False 渐进启用；CORS 用 loopback 任意端口正则（Flutter web dev server 端口随机），前端 api_config 注入头与后端启用排期对齐。
  - 长任务 60s 超时（综述/简历/讲解）：map-reduce 单段 <4000 字符 + llm_client 超时提到 120s + task_progress 分步进度让用户看到进行中，杜绝超时即黑屏。
  - WPS 兼容性：docx/xlsx 导出必须逐类实测（中文字体 qn('w:eastAsia')、页边距、表格、xlsx 打开无损坏提示）；P3 统一导出服务收口，避免各处自写导致格式漂移。
  - LLM 幻觉编造经历/引用：证据链契约强制（无 source_document_id 的行标【待补充】且 AI 生成不打入）+ 确认门分级（档案高信任区强制三步确认）+ prompt 改动跑回归集。
  - EasyOCR 在运行环境重/缺依赖：OCR 全部走 services/ocr_service 集中封装，失败返回可解析占位文本；演示现场预置文字版 PDF/文本导入兜底，OCR 不作为硬依赖。
  - 多表 seed/clear FK 顺序错误导致清空失败：clear 按逆依赖序批量删除 + demo-status 返回各表计数便于验证；seed/clear 均幂等（重复调用安全）。
  - 演示态误伤真实数据：DEMO_ACTIVE 隔离钩子挂在 run() 前置 + redaction 对真实敏感字段强制打码；seed 与 clear 只写/只清演示态数据，正式数据不动。
  - skills 数量膨胀导致 S1-S3 又堆硬编码 prompt：注册表统一 Skill 元数据 + prompts 版本化 + 回归集校验，硬约束「S1-S3 禁止大改基座」。

### AI/提示词实现架构师

**实现策略**：本领域 = 技能注册表 + 意图路由 + 证据链契约 + 长任务分段，对应 P-1/P-2/P-9/P-10 的 AI 侧落地。

【核心决策】
1. 技能注册表重构 llm_service.py：统一入口 run(task, payload, *, db, ctx)。现有 9 个硬编码方法保留为薄委托（→run()），保证 inbox/documents/ai_report/ai_consult 六路由零行为变化迁移。S0 先迁移 classify/extract_todos/extract_exams/generate_summary 打样，其余随域迁移。run() 管道 = 输入 schema 校验 → 知情同意钩子 → 脱敏钩子 → 缓存查询 → prompt 渲染 → LLM 调用（指数退避重试）→ 输出 schema 校验（取代裸 _parse_json）→ 证据链校验 → 审计 → 缓存回写。
2. 意图路由（场景4）：两层路由。快路径 = 声明式 route_table（关键词/正则 → {domain, task, params}，高置信直达）；慢路径 = orchestrate 技能（LLM）兜底，意图不明返回 clarification 澄清问题而非硬路由。统一返回 RoutingDecision{domain, task, params, reply, confidence, clarification, sources}。
3. 证据链契约（P-2）：统一 EvidenceItem{source_document_id, chunk_id, page, confidence, source_title, quote}，定义在 backend/app/schemas/evidence.py 并作为 ADR 冻结契约。所有技能输出带断言级 evidence；无来源断言强制标【待补充】；落库/入 artifact 前校验，无来源断言丢弃。
4. 长任务（P-9）：同步阻塞 + map_reduce 分段（单段 < 4000 字符）+ TaskProgress 表轮询。综述/对比/简历长流程走 MapReduceRunner，分步更新 current_step/step_label，前端 AiTaskPanel 消费。新增 TaskProgress 表，随启动幂等 create_all 新建（不改老表）。
5. MockLLM 回归集 ≥15 条锁定迁移行为；26 个 prompt 各配 schema 单测 + 缺失占位符 lint。LLM_MOCK 开关 + 演示预生成结果兜底（林小夏 fixtures），保证断网可演示。
6. 依赖零新增：prompt 用 {{var}} 自定义模板（SafeDict）而非 Jinja2；缓存用内存 LRU；分段逻辑新写 map_reduce.py 不动 text_utils。
7. 演示模式：consent 豁免 + redaction 跳过（保流畅），但敏感字段标记仍输出；LLM 失败/断网时 MockLLM 预生成结果兜底。

4. 长任务演示：literature_review 用 3 篇预置论文跑 map-reduce，AiTaskPanel 轮询展示"正在生成第3/5节"分步进度，是现场展示工程化的加分幕。

  - prompt 变量注入/缺失导致渲染异常 → {{var}} 占位符成对校验（test_prompts lint）+ payload 经 pydantic schema 校验 + redaction 前置钩子打码敏感输入
  - 缓存脏数据：改 prompt 后命中旧缓存 → 缓存 key 必须含 prompt version，改 prompt 即升 version（frontmatter）
  - 演示环境断网/LLM 慢 → LLM_MOCK 开关 + 预生成结果兜底 + 演示模式豁免确认门；MockLLM fixtures 随 seed 包一起交付

### 安全/工程实现架构师

**实现策略**：本领域覆盖四块：安全三件套（API本地加固+CORS+本地令牌、字段级脱敏+仅本地/可云端标记、知情同意）、演示模式工程侧（DemoSafe+seed/clear）、P1加固（AuthLock/字段加密/审计/一键导出与彻底删除）、测试门禁与运行形态锁定。关键决策：①运行形态锁定=单一形态「Flutter Web构建产物由FastAPI静态托管」，浏览器仅需一个URL（http://127.0.0.1:8002），单进程启动、同源请求、不依赖WPS；开发态用`flutter run -d chrome`（随机端口）靠CORS正则白名单放行，两者共用同一套X-Local-Token与安全中间件。②CORS从`allow_origins=["*"]+allow_credentials=True`收紧为localhost正则白名单+allow_credentials=False（token走Header非Cookie）。③X-Local-Token首启自生成并持久化到data/local_token.txt，由/api/config下发给前端（威胁模型=仅本机，写ADR明确不承诺云端级安全），中间件校验，豁免OPTIONS/health/config/privacy-status。④脱敏作为llm_service.run()前置钩子统一生效：传输前打码、打码后落库（保住ILIKE检索性能），敏感字段带sensitive/visibility标记，前端SensitiveField消费。⑤知情同意用consent服务+app_settings表，首用/跨敏感边界/导出三类，未同意则run()返回consent_required而非执行；演示模式默认豁免；设置页可撤销。⑥演示隔离采用demo_seed追踪表（seed时记录各表行id，clear_demo只删演示行，不污染正式数据），demo ON→全局隐藏敏感字段+AI调用拦截+豁免解锁/确认。⑦新增表全部走create_all幂等只建新表，不ALTER老表。⑧测试门禁=MockLLM依赖注入+pytest（内存sqlite），回归集≥15条+安全用例+六幕剧本E2E冒烟+gate.py一键执行；S0即建成，S1–S3禁大改基座。
